# 5.3.7 — Audit ostalih modula i privatnost

Datum: 2026-10-09

Opseg: preostalih 8 ekrana iz §4.7 plana 5.3 + **namjenski editor obavještenja o privatnosti**.
Bez izmjena poslovnih pravila; backend dodaje samo API za editor (upisuje postojeće dvije postavke).

## Namjenski editor obavještenja o privatnosti — isporučeno

- **Backend** (`privacy/record/privacy-notice-admin.controller.ts`, nov):
  - `GET /privacy/notice/status` — stanje modula, obje sirove tekstualne vrijednosti i `maxLength`;
  - `GET /privacy/notice/draft?locale=bs|en` — nacrt koji bi javna stranica prikazala (isti `buildNoticeDraft` kao javni endpoint);
  - `PUT /privacy/notice` — čuva **oba jezika u jednoj transakciji** kroz `SettingsService.setSettingValues` (audit i realtime neovisni o editoru).
  - Sve traži `privacy.manage` (SUPER_ADMIN u default mapi); limit 20.000 znakova je sada zajednička konstanta `privacyNoticeMaxLength` (registry i API validiraju isto).
- **Frontend**:
  - novi tab **Obavještenje** u Privatnost (`?tab=notice`, vidljiv uz `privacy.manage`): BS/EN segmenti, Markdown editor s pregledom uživo, brojač znakova (`aria-live`), dugme **„Generiši iz evidencije obrade“**, oznaka stanja *Objavljeno (vlastiti tekst)* / *Nacrt generisan iz evidencije* / *Modul isključen*, indikator nesačuvanih izmjena; čuvanje je onemogućeno dok je tekst preko limita;
  - javna stranica prikazuje **oznaku nacrta** (`privacy-notice-draft-badge`) kad je tekst generisan iz evidencije;
  - detail-dijalog postavke `private.privacy.notice.*` ima link **„Otvorite editor obavještenja“** → `/privacy?tab=notice`.
- **Testovi**: vitest (`privacy-view`: stanja i vidljivost taba), jest (kontroler: oblik odgovora, transakcija oba ključa, validacija limita i lokala), E2E `43-privacy-notice-editor.spec.ts` (generisanje → čuvanje → javna stranica bez oznake nacrta → prazan jezik s oznakom nacrta → vraćanje originala; link iz postavki).
