# Paket 1.1 — Prosljeđivanje (eskalacija) tiketa između grupa i OU-a

Status: **implementirano** (2026-09-25, odobreno) · Faza 1 · procjena ~3,5 RD · vidi §13
Izvor: RAW §Tiketi („Prosljeđivanje/eskalacija", „Cross-OU forwarding"), settings
`private.ticket.forwarding.*`, permisija `ticket.forward.cross_ou`, participanti
`FORWARDED_FROM_GROUP` / `FORWARDED_TO_GROUP`; audit gap G1.

## 1. Poslovni scenario

Korisnik iz OU **Zenica** prijavi tiket za servis *Telefonija*; routing ga dodijeli grupi
**Telefonija (Zenica)**. Agenti te grupe utvrde da tiket može riješiti samo **Telefonija
(Direkcija)** (posebne ovlasti) i proslijede ga uz razlog. Agenti Direkcije tiket vide u svom
inboxu, rješavaju ga i komuniciraju s korisnikom. Zenica ga i dalje vidi kao tiket iz svog OU-a,
ali on više nije u njihovom radnom redu.

„Eskalacija" u ovom sistemu = prosljeđivanje na grupu koja ima potrebne ovlasti (isti ili drugi
OU). Automatske SLA eskalacije (obavijesti pri kašnjenju) ostaju zaseban, postojeći mehanizam.

## 2. Odluke vlasnika (2026-09-25)

| # | Odluka |
|---|---|
| D1 | **Članovi grupe kojoj je tiket trenutno dodijeljen dobijaju puni (staff) pristup** tom tiketu, bez obzira na OU tiketa. Pristup prestaje kad tiket ode drugoj grupi. |
| D2 | Prethodna grupa **i dalje vidi tiket kroz svoj OU scope**, ali ga ne rješava (nije u njenom inboxu). Obavijesti dobija samo ako je ostavljena kao posmatrač (postavka `keepPreviousHandlersAsWatchers`). |
| D3 | Cross-OU prosljeđivanje smije **AGENT i ADMIN s permisijom `ticket.forward.cross_ou`** (po defaultu data objema ulogama, može se oduzeti). Unutar istog OU-a prosljeđuje svaki staff korisnik tiketa. SUPER_ADMIN uvijek. |
| D4 | **SLA rok teče dalje** (ne resetuje se); dodijeljeni agent se uklanja; status → `PENDING` (Na čekanju), nakon čega nova grupa preuzima ili se primjenjuje njena auto-dodjela. |

## 3. Pravila domene

1. Prosljeđivanje je dozvoljeno samo u statusima `UNROUTED`, `PENDING`, `ASSIGNED`,
   `IN_PROGRESS`, `WAITING_FOR_USER`, `ON_HOLD` (ne za `RESOLVED`, `CLOSED`, arhivirane,
   spojene tikete i u read-only modu).
2. Ciljna grupa mora postojati i biti različita od trenutne (`FORWARD_SAME_GROUP`).
3. Cross-OU = OU ciljne grupe ≠ OU trenutne grupe (ako trenutne nema — ≠ OU tiketa).
   Zahtijeva: postavku `allowCrossOu = true` **i** permisiju `ticket.forward.cross_ou`
   (u scope-u koji pokriva OU tiketa), inače `FORWARD_CROSS_OU_FORBIDDEN`.
4. Razlog: obavezan ako `requireReason = true` (default), 10–1000 znakova, normalizovan kao
   ostali tekst, prolazi kroz redaction pravila prije upisa u audit.
5. Akter mora imati staff pristup tiketu (OU scope ili članstvo u trenutnoj grupi — D1). Agent
   koji je samo AGENT smije prosljeđivati samo tikete svoje trenutne grupe (isto pravilo kao bulk).
6. Opcionalno ciljni agent: mora biti član ciljne grupe; tada status → `ASSIGNED`.
7. Povjerljivi tiket: dozvoljeno; ciljna grupa pristup dobija kroz postojeće pravilo
   „dodijeljena grupa". Akter se upozorava u UI-ju da će nova grupa vidjeti sadržaj.
8. Posljedice (jedna transakcija):
   - `assignedGroupId` = cilj, `assignedUserId` = null (ili ciljni agent), status po D4/pravilu 6;
   - participanti: `FORWARDED_FROM_GROUP` (stara), `FORWARDED_TO_GROUP` (nova),
     `HANDLER_GROUP` sinhronizovan; ako `keepPreviousHandlersAsWatchers`, prethodni
     dodijeljeni agent ostaje participant (posmatrač);
   - zapis u novoj tabeli `TicketForwardEvent` (historija za izvještaje);
   - sistemski događaj u razgovoru (vidljiv staffu; korisniku neutralna poruka
     „Tiket je proslijeđen timu X" — po postavci `notifyRequester`, default true, bez razloga);
   - audit log (`ticket.forwarded`, cross-OU označen) + change log (before/after);
   - SLA: bez promjene rokova; pauze se ne diraju.
9. Poslije commita: auto-dodjela ciljne grupe (ako je ona konfigurisana), notifikacije, realtime.
10. Vraćanje: akcija „Vrati prethodnoj grupi" je prosljeđivanje na `FORWARDED_FROM_GROUP`
    posljednjeg događaja (isti tok, razlog obavezan).

## 4. Pristup (D1) — izmjene

| Mjesto | Izmjena |
|---|---|
| `resolve-ticket-actor-access.ts` | staff pristup i kad je akter član `ticket.assignedGroupId` i ima AGENT/ADMIN ulogu (bilo gdje) |
| `authorize-ticket-actor.ts` (mutacije) | isto pravilo za odgovor, promjenu statusa, preuzimanje, time log |
| `list/build-ticket-visibility-where.ts` | manage scope = `OR(originUnitId IN scope, assignedGroupId IN actorGroupIds)` za AGENT/ADMIN |
| inbox grupe / counts / dashboard | koriste isti where — provjeriti paritet (`visibility-parity-world`) |
| Pretraga, izvoz, report scope | isto pravilo; ADMIN izvještaji ostaju po OU-u |

Performanse: `actorGroupIds` se već učitava; `assignedGroupId` je indeksiran. Kapija DB upita
se ne smije pomjeriti (provjera `query-count` testovima).

## 5. Model podataka (aditivna migracija)

```prisma
model TicketForwardEvent {
  id            String   @id @default(cuid())
  ticketId      String
  fromGroupId   String?
  toGroupId     String
  fromUnitId    String?
  toUnitId      String
  actorUserId   String?
  reason        String
  isCrossOu     Boolean
  createdAt     DateTime @default(now())
  // relacije: Ticket (Cascade), Group (SetNull/Restrict), User (SetNull)
  @@index([ticketId, createdAt])
  @@index([toUnitId, createdAt])
}
```

## 6. API

| Metoda | Ruta | Opis |
|---|---|---|
| `GET` | `/tickets/:id/forward-targets?q=` | grupe u koje akter smije proslijediti: naziv, OU (puna putanja), `isCrossOu`, broj aktivnih agenata; grupe van dozvole se ne vraćaju |
| `POST` | `/tickets/:id/forward` | `{ targetGroupId, targetUserId?, reason, keepMeAsWatcher? }` → ažuriran tiket |
| `GET` | `/tickets/:id/forward-history` | lista `TicketForwardEvent` (staff) |

Greške (bs/en poruke): `FORWARD_NOT_ALLOWED_IN_STATUS`, `FORWARD_SAME_GROUP`,
`FORWARD_CROSS_OU_FORBIDDEN`, `FORWARD_CROSS_OU_DISABLED`, `FORWARD_REASON_REQUIRED`,
`FORWARD_TARGET_USER_NOT_MEMBER`, `HANDLER_GROUP_NOT_FOUND`, `FORBIDDEN`.
Rate limit: postojeći mutacijski limiter.

**Bulk paritet**: `assign_group` u bulku koristi isti servis (`forwardTicket`) — obavezan razlog
u bulk dijalogu, cross-OU provjera, isti participanti i historija.

## 8. Notifikacije i realtime

- Novi događaj `ticket.forwarded`: in-app + e-mail članovima ciljne grupe (ili ciljnom agentu),
  in-app prethodnom agentu; korisniku po `notifyRequester` (bez razloga i bez naziva OU-a).
- E-mail šablon `ticket.forwarded` (bs; en dolazi u paketu 1.5).
- Teams stub lista događaja proširena `ticket.forwarded`.
- WebSocket: `ticket.updated` + inbox obje grupe osvježen (`group:<id>` sobe).

## 9. Frontend

- Detalj tiketa, traka akcija: **„Proslijedi"** (ikona) → dijalog:
  - pretraga grupa (grupisano po OU; oznaka „drugi OU" i upozorenje);
  - opcionalni izbor agenta ciljne grupe;
  - razlog (brojač znakova, obavezan);
  - checkbox „Ostavi me kao posmatrača";
  - upozorenje za povjerljive tikete.
- „Vrati prethodnoj grupi" (brza akcija kad postoji historija).
- Tab/sekcija **Historija prosljeđivanja** (od → do, OU, ko, kad, razlog).
- Lista tiketa: indikator „proslijeđen" i filter „proslijeđeni u moju grupu".
- Bulk dijalog dodjele grupe: polje razlog + ista pravila.
- Admin → Postavke: grupa „Prosljeđivanje" (automatski iz registryja).
- i18n bs/en za sve nove ključeve; kontrast audit.

## 10. Testovi

## 13. Implementacija — bilješke i odstupanja

- API dodatno: `GET /tickets/:id/forward-targets/:groupId/agents`. Vraća agente ciljne grupe
  za opcionalni izbor. Odgovara samo za grupe koje akter smije koristiti, pa članstvo grupe
  druge OJ nije vidljivo bez cross-OU prava.
- Server-side matrica akcija (`resolve-ticket-allowed-actions.ts`) dobila je `forward`, pa
  UI nudi „Proslijedi" samo kad bi server prihvatio zahtjev. Status i OU se i dalje
  provjeravaju po cilju.
- „Vrati prethodnoj grupi" je dugme u dijalogu (`previousGroupId` iz `forward-targets`), a ne
  zasebna ruta. Greška `FORWARD_NO_PREVIOUS_GROUP` je rezervisana.
- Uloga AGENT podrazumijevano ima `ticket.forward.cross_ou` (postojeća definicija uloge, nije
  mijenjana). D3 zato u praksi znači setting + OU opseg dodjele. Ograničenje na pojedine
  agente radi se kroz uloge i policy pakete (dokumentovano u
  `docs/user-guide/prosljedjivanje-tiketa.md`).
- **Dugme „Dodijeli" uklonjeno** (odluka 2026-09-25). Zamjena je „Proslijedi" s trenutnom
  grupom i odabranim kolegom, tj. preraspodjela unutar grupe. Pravila preraspodjele:
  - agent je obavezan;
  - razlog nije obavezan;
  - nema `FORWARDED_*` participanata;
  - podnosilac ne dobija obavijest;
  - historija prikazuje oznaku „Preraspodjela" (`fromGroupId === toGroupId`).

  Iz matrice akcija uklonjen je `assign`. Grupna akcija „Dodijeli agentu" na listi ostaje,
  jer je to masovna funkcija.
- Uloga AGENT zadržava cross-OU pravo (odluka vlasnika: bez ograničavanja).
- **Preneseno u paket 1.6** (zahtijeva izmjenu liste pod query-count kapijom):
  - indikator „proslijeđen" i filter „proslijeđeni u moju grupu" na listi tiketa;
  - brojač prosljeđivanja na tiketu.

  Izvještaj „≥ 3 prosljeđivanja" ide u paket 1.6. Podaci već postoje u
  `TicketForwardEvent`, s indeksima po `toGroupId`/`toUnitId`.
- Testovi:
  - backend `forwarding/forward-ticket.spec.ts` (10 scenarija, uklj. agents endpoint);
  - D1 paritet u postojećim specovima;
  - frontend `ticket-forwarding.spec.ts`;
  - E2E `e2e/tests/10-forward-cross-ou.spec.ts`: SuperAdmin kroz dijalog → grupa druge OJ →
    inbox + claim agenta → cross-OU vraćanje.
