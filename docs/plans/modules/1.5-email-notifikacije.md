# Paket 1.5 — E-mail notifikacije, profesionalni nivo

Status: **implementirano 2026-09-25** (odobreno uključujući E4, E8 dopunjen, E10 dodan) — vidi §11 · Faza 1 · procjena ~3,5 RD
Izvori:
- RAW §Notifikacije („in-app + email (Office 365)");
- RAW §i18n: „EN postoji kao fallback … email templates" i ključevi `private.i18n.*`;
- RAW §Email delivery scope (internal-only + allow-list);
- gap **G7**, preporuka **P2**; priprema za paket 2.3 (odgovor e-mailom).

## 1. Stanje danas (šta tačno fali)

| Oblast | Danas | Problem |
|---|---|---|
| Format | samo `text/plain`, jedna rečenica | izgleda kao spam, nema strukture ni brenda |
| Link na tiket | nema | korisnik mora sam tražiti tiket (najčešći razlog ignorisanja) |
| Jezik | samo bs | RAW traži EN fallback za e-mail šablone |
| Povjerljivi tiketi | naslov zamijenjen brojem | usluga i sadržaj se ne šalju, ali to nije eksplicitno pravilo; RESTRICTED usluge se ne tretiraju |
| Sadržaj poruke | ne šalje se | kod „Nova poruka" korisnik ne zna šta mu je odgovoreno bez otvaranja aplikacije |
| Uređivanje šablona | samo sirovi JSON u registry postavci | nema pregleda ni testnog slanja; greška u JSON-u tiho vraća default |
| Threading | nema `Message-ID`/`In-Reply-To` | Outlook svaki e-mail prikazuje kao novi razgovor |
| Auto-odgovori | nema `Auto-Submitted` | „Out of office" odgovori se vraćaju na adresu pošiljaoca (petlje) |
| Performanse fan-outa | `user.findUnique` po primaocu (N+1) | kod grupe od 30 članova 30 upita |
| Broadcast e-mail | šalje se samo usput, kao AGENT_REPLY | ako je in-app broadcast isključen, a e-mail uključen, ne ide ništa |

## 2. Ciljevi i ne-ciljevi

Ciljevi:
- brendiran, responzivan HTML e-mail s tekstualnom alternativom;
- dugme „Otvori tiket" u svakoj ticket poruci;
- jezik po korisniku;
- sigurna pravila za povjerljive tikete;
- admin uređivanje šablona s pregledom i testnim slanjem;
- threading i zaštita od auto-odgovora.

Ne-ciljevi:
- čitanje odgovora iz sandučića (paket 2.3);
- korisnički izbor koje događaje prima e-mailom (paket 2.2);
- slike ili logo sa vanjskog URL-a (Outlook ih blokira, vidi §4.4).

## 3. Odluke za odobrenje

| # | Prijedlog |
|---|---|
| E1 | **Šablon = tekst, raspored = kod.** Admin uređuje naslov, uvod, tekst dugmeta i podnožje (plain tekst s placeholderima). HTML raspored je fiksan u kodu. Admin tako ne može pokvariti prikaz niti ubaciti HTML ili skriptu, a sve vrijednosti se escapeuju. |
| E2 | **Jezik**: novo polje `User.preferredLocale` (`bs` \| `en` \| null). Postavlja se automatski kad korisnik promijeni jezik u aplikaciji. Ako je null, koristi se `private.i18n.defaultLocale` (bs). Ako šablon na tom jeziku ne postoji, koristi se `private.i18n.fallbackLocale` (en), a na kraju ugrađeni bs. |
| E3 | **Povjerljivo** (`isConfidential` ili usluga klasifikacije `CONFIDENTIAL`/`RESTRICTED`): naslov i tekst sadrže samo broj tiketa i generičku rečenicu. Ne šalju se naslov, usluga, isječak poruke ni ime grupe. Link ostaje, a pristup provjerava aplikacija. |
| E4 | **Isječak poruke** kod „Nova poruka": samo javni odgovori (USER_REPLY/AGENT_REPLY, nikad interna bilješka), nakon redakcije osjetljivih podataka, najviše 600 znakova. Postavka `private.notifications.email.includeMessageExcerpt` (default **da**). |
| E5 | **Link**: `APP_PUBLIC_URL` iz env-a (već postoji za Edge ekstenziju). Bez njega e-mail ide bez dugmeta, uz upozorenje u logu i na admin kartici SMTP-a. Link je uvijek `…/tickets/<id>` i ne nosi token (nema „magic link" prijave). |
| E6 | **Threading**: `Message-ID` jedinstven po poruci. `In-Reply-To` i `References` pokazuju na stabilni korijen `<ticket-<id>@<domena>>`. Naslov uvijek počinje s `[<broj tiketa>]`. Outlook i Gmail tako grupišu razgovor, a paket 2.3 prepoznaje tiket po zaglavlju i po broju u naslovu. |
| E7 | **Zaštita od petlji**: `Auto-Submitted: auto-generated` i `X-Auto-Response-Suppress: All` (Exchange tada ne šalje OOF i obavijesti o čitanju). |
| E8 | **Način odgovora, bira se u postavkama** (`private.notifications.email.replyMode`). **A `no_reply`** (zadano): podnožje kaže „Ne odgovarajte — odgovorite u aplikaciji", bez `Reply-To`. **B `shared_mailbox`**: `Reply-To` je `private.notifications.email.replyToAddress` (obavezno kod B; ako nedostaje, sistem pada na A uz upozorenje na admin kartici), a podnožje kaže da se na poruku može odgovoriti. Odlaznu stranu B-a (Reply-To, threading, `[broj]` u naslovu) daje 1.5. Čitanje sandučića i pretvaranje odgovora u poruku na tiketu dolazi u 2.3, isto modularno: IMAP (OAuth2 ili lozinka), Microsoft Graph i Gmail API. |
| E10 | **Modularni provajder slanja** (`private.smtp.provider`): `o365` (smtp.office365.com:587 STARTTLS), `gmail` (smtp.gmail.com:587, app password) i `smtp` (bilo koji server, npr. interni Exchange ili Postfix). Preset popunjava host, port i TLS kad host nije upisan, a upisane vrijednosti imaju prednost. Slanje ide kroz postojeći `MailTransport` interfejs, pa se API provajderi (Microsoft Graph `sendMail`, Gmail API) dodaju kao nova implementacija bez izmjena u ostatku sistema. Planirani su uz 2.3, gdje ionako traže istu registraciju aplikacije. |
| E9 | Nema vanjskih slika. Brend čine `public.branding.appName` kao tekstualni znak i nova postavka `private.notifications.email.accentColor` (default indigo `#4f46e5`, provjera kontrasta AA). |

## 4. Rješenje

### 4.1 Model šablona (registry v2, kompatibilan unazad)

Postojeća postavka `private.notifications.templates.registryJson` dobija verziju 2:

```json
{
  "version": 2,
  "locales": {
    "bs": { "ticket.created": { "subject": "...", "heading": "...", "body": "...", "cta": "...", "footer": "..." } },
    "en": { "...": {} }
  }
}
```

- Stari format (v1, ključ → `{subject, body}`) čita se kao bs nadjačavanje. Postojeća
  instalacija ne gubi izmjene.
- Polja koja nedostaju uzimaju se iz ugrađenog defaulta, po polju, za svaki jezik posebno.
  Neispravan unos se odbija **pri spremanju** (400 s tačnim poljem), umjesto da se pri slanju
  tiho vrati default.
- Ugrađeni defaulti: kompletni bs **i** en za svih 10 ključeva: 9 ticket događaja (uklj.
  `ticket.forwarded`) i `user.temporary_password`.

Placeholderi (allow-list, svi se escapeuju):

| Grupa | Placeholderi |
|---|---|
| Postojeći | `ticketNumber`, `ticketTitle`, `ticketId`, `type`, `event` |
| Novi | `ticketUrl`, `recipientName`, `serviceName`, `statusLabel`, `priorityLabel`, `groupName`, `actorName`, `appName` |

Isječak poruke se ne ubacuje placeholderom, nego ga dodaje raspored kao zaseban blok (E4). Labele
statusa i prioriteta prevode se na jezik primaoca.

### 4.2 Rendering

`render-email-message.ts` → `{ subject, html, text }`:
- HTML je tabelarni raspored širine 600 px s inline CSS-om. Radi u Outlook desktopu (Word
  engine), OWA, Gmailu i na mobilnom.
- Podrška za tamni način (`color-scheme`), a dugme ima i „bulletproof" VML varijantu za
  Outlook.
- Blokovi su redom:
  - zaglavlje (appName);
  - naslov;
  - uvod;
  - kartica tiketa (broj, naslov, usluga, status, prioritet; u povjerljivom režimu samo broj);
  - isječak poruke;
  - dugme;
  - podnožje (razlog primanja + napomena o odgovoru, E8).
- `text/plain` alternativa se generiše iz istih podataka: naslov, polja, isječak i puni URL.
- Sve vrijednosti prolaze kroz `escapeHtml`. Uklanjaju se kontrolni znakovi, a naslov ne smije
  sadržavati `\r\n` (zaštita od umetanja zaglavlja).

### 4.3 Isporuka

- `fanOutEmailNotifications`:
  - primaoci se učitavaju jednim `user.findMany` (email, displayName, preferredLocale);
  - poruka se renderuje **po jeziku**, ne po primaocu (najviše 2 renderinga po događaju).
- `PreparedOutboundEmail` dobija opcionalna polja `html`, `headers` i `messageId`:
  - stari poslovi u redu (samo `text`) i dalje prolaze;
  - parser queue payloada prihvata oba oblika.
- `SmtpMailTransport` šalje `text`, `html`, `replyTo`, `messageId`, `inReplyTo`,
  `references` i dodatna zaglavlja.
- Dedupe (`userId + dedupeKey`) ostaje kakav jeste.

### 4.4 Zašto bez logotipa

Outlook blokira vanjske slike dok korisnik ne klikne „preuzmi slike". Ugrađena slika (CID)
povećava svaki e-mail za 10–40 KB i često završi kao „prilog". Tekstualni znak i boja daju
profesionalan izgled bez tih problema. CID logo se može dodati kasnije, kao opcija, bez
izmjene šablona.

### 4.5 Povjerljivost (E3), detaljno

`resolveEmailSensitivity(ticket, service)` → `normal` | `confidential`. U režimu
`confidential` vrijedi sljedeće:
- `ticketTitle` = broj tiketa;
- `serviceName` i `groupName` su prazni;
- nema isječka poruke;
- naslov e-maila koristi poseban `subjectConfidential` iz šablona, uz generički default;
- dodaje se oznaka „Povjerljivo".

Pravilo se testira za svaki od 9 ticket ključeva.

### 4.6 Broadcast

Kad je `broadcastEnableEmail` uključen, broadcast se šalje e-mailom bez obzira na in-app
postavku. Koristi se novi ključ šablona `ticket.broadcast`, a isječak je sama poruka broadcasta.
Rate limit i pregled broja primalaca ostaju.

### 4.7 Jezik korisnika (E2)

- Migracija: `User.preferredLocale String?` (aditivna, bez backfilla).
- `PATCH /users/me/preferences { locale }` (novo, samo za vlastiti nalog).
- Frontend `changeLocale` poziva ovu rutu, a trenutni jezik šalje i pri prijavi ako polje još
  nije postavljeno.
- Registruju se RAW postavke `private.i18n.defaultLocale` (bs),
  `private.i18n.fallbackLocale` (en) i `private.i18n.supportedLocalesCsv` (bs,en).

## 5. Admin UI

Postavke → **E-mail šabloni** (nova kartica, uz postojeću SMTP karticu):
- lista događaja × jezik (bs/en), s oznakom „izmijenjeno" ili „zadano";
- uređivač sadrži:
  - polja naslov, naslov (povjerljivo), uvod, tekst dugmeta i podnožje;
  - „čipove" placeholdera koji se ubacuju klikom;
  - provjeru nepoznatih placeholdera u realnom vremenu;
- **Pregled** uživo (iframe sandbox) na primjeru tiketa, s prekidačem normalno/povjerljivo i
  prikazom HTML/tekst;
- **Pošalji test na moju adresu**: stvarno slanje kroz trenutni SMTP. Rate limit je 5 u 10
  minuta, akcija se audituje, a rezultat SMTP-a se prikazuje;
- **Vrati na zadano** po šablonu;
- spremanje ide kroz postojeći settings tok (razlog izmjene, audit, verzionisanje
  konfiguracije).

API (SUPER_ADMIN / ADMIN s `settings.write`):

| Metoda | Ruta | Opis |
|---|---|---|
| `GET` | `/settings/email-templates` | efektivni šabloni (default + izmjene) i lista placeholdera |
| `PUT` | `/settings/email-templates` | validacija + spremanje (razlog obavezan) |
| `POST` | `/settings/email-templates/preview` | `{ key, locale, sensitivity, draft? }` → `{ subject, html, text }` |
| `POST` | `/settings/email-templates/test` | šalje renderovani nacrt na e-mail pozivaoca |

Kartica SMTP-a dobija i status „`APP_PUBLIC_URL` nije postavljen — e-mailovi nemaju link".

## 7. Testovi

- Unit:
  - renderer: escapeovanje (`<script>`, `"`, CRLF u naslovu);
  - svaki ključ × bs/en × normalno/povjerljivo, uz snapshot teksta;
  - fallback lanac jezika;
  - v1 → v2 kompatibilnost;
  - validacija pri spremanju.
- Fan-out:
  - jedan upit za primaoce;
  - najviše 2 renderinga;
  - interna bilješka nikad ne ide u isječak;
  - povjerljiv tiket bez naslova i usluge;
  - `Message-ID`, `In-Reply-To`, `Auto-Submitted` prisutni;
  - queue payload stari i novi format.
- Broadcast e-mail s isključenim in-app kanalom.
- Frontend vitest: uređivač (nepoznat placeholder, reset), pregled.
- E2E `11-email-templates.spec.ts`: izmjena šablona → pregled → test slanje. Postojeći SMTP
  sink (`E2E_SMTP_*`) provjerava da poruka ima HTML dio, link i `[broj]` u naslovu.

## 8. Isporuka

1. Migracija `User.preferredLocale` (aditivna).

## 10. Rizici

| Rizik | Mjera |
|---|---|
| Outlook desktop loše renderuje CSS | tabelarni raspored, inline stilovi, VML dugme; provjera u OWA + Outlook 365 prije pilota |
| O365 odbije HTML kao spam | isti pošiljalac kao danas (SPF/DKIM domene), bez vanjskih slika i skraćenih linkova, uvijek tekstualna alternativa |
| Izmjena šablona pokvari e-mailove | validacija pri spremanju, pregled, test slanje, reset; raspored nije uređiv |
| Curenje povjerljivog sadržaja | E3 + test po ključu; isječak samo iz javnih poruka, nakon redakcije |
| Stari poslovi u redu nakon deploya | parser prihvata stari payload (samo `text`) |
