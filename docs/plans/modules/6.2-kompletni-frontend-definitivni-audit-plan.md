Za svaki fresh nalaz primijenjena su četiri koraka:

1. **Dokument poređenje** — tražen je isti ili sadržajno ekvivalentan nalaz u auditima 01–16.

   - **OTVOREN** — problem postoji u trenutnom kodu;

## Faza 4 — Jedinstveni partial-resource error ugovor

**Nalaz:** DF4  
**Cilj:** request greška se nikada ne prikazuje kao dokaz da poslovni podatak ne postoji.

### Scope

- Users services options;
- Groups routing rules;
- user role scope summaries;
- policy packs service options;
- service mutation policy-pack options;
- article-from-reply knowledge categories.

### Implementacija

1. Uvesti neutralni model:

```ts
type PartialResource<T> = {
  data: T | null;
  errorKey: TranslationKey | null;
  requestId: string | null;
  isLoading: boolean;
  isRefreshing: boolean;
  retry: () => Promise<void>;
};
```

2. Ne uvoditi jedan globalni mega-hook; koristiti zajednički ugovor i domenske controllere.
3. Sačuvati stale podatke pri refresh grešci.
4. Initial failure prikazuje unavailable + Retry, ne empty.
5. Zavisni select/akcija je onemogućena dok podaci nisu pouzdani.
6. Existing saved ID ostaje očuvan kada options endpoint padne.

### Testovi

Za svaki scope:

- initial failure;
- retry success;
- stale data + refresh failure;
- nema lažne prazne liste/nule;
- save ne briše nevidljivu postojeću vrijednost.

### Acceptance

- nema konfiguracijskog `catch(() => [])` obrasca u navedenom scopeu;
- request ID je prikazan kada postoji;
- partial failure ne blokira nezavisni dio ekrana.

### Rezultat implementacije (21.10.2026.)

- uveden je neutralni generički `PartialResource<T, ErrorKey>` ugovor i mali lifecycle controller; domenski loaderi i error mapperi ostaju u vlasništvu pojedinačnih modula;
- controller razlikuje initial loading od refreshinga, čuva posljednje uspješne podatke pri refresh grešci, propagira request ID i izlaže eksplicitni `retry`;
- Users service options, Groups routing-rule counts, user-role scope summaries, Policy Packs service options, service-mutation policy-pack options i article-from-reply kategorije više ne pretvaraju request kvar u uspješnu praznu listu;
- initial failure prikazuje mapiranu grešku, request ID kada postoji i Retry; nezavisni dio ekrana ostaje upotrebljiv;
