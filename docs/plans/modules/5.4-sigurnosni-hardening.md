# Paket 5.4: Sigurnosni hardening (phishing-otporan MFA, konfigurabilni limiti, CAPTCHA, politika sesija)

> Status: **dizajn revidiran 2026-10-09 — odobren za implementaciju (5.4.0-a)** · Procjena: ~5–6 RD · Izvor: REVIEW_ANALIZA 5.2.4 closeout (preostale sigurnosne stavke), RAW §29 (SuperAdmin lokalni-only), §20 (revizija pristupa), §M2 iz 2026-10-02 dependency/MFA/rollback reviewa, dopuna nakon vlasnikove odluke (2026-10-08: "definitivno dizajn za 5.4").
>
> **Revizija 2026-10-09 (pregled dizajna s vlasnikom, prije 5.4.0-a):** dizajn iz 2026-10-08 provjeren protiv aktualnog koda (nakon 5.3) i izmijenjen:
> 1. **M6 bez nove tabele** — sigurnosni dnevnik se gradi na postojećem audit logu (već vodi `auth.mfa_*` i `auth.password_*` akcije); nova `SecurityEvent` tabela ne uvodi se (odluka vlasnika: proširiti audit log).
> 2. **Passkey step-up se podržava** — potvrda osjetljivih akcija (privatnost: izvoz, anonimizacija) prihvaća WebAuthn assertion, ne samo TOTP kod (odluka vlasnika).
> 3. **HIBP uključen po defaultu** (odluka vlasnika), uz fail-open kad mreža nije dostupna (offline self-host ne smije biti blokiran od promjene lozinke).
> 4. **M4/M5 suženi** — device info u sesijama, obavijest o novom uređaju, password historija/blocklist/istek i kolona `mustChangePassword` **već postoje** u kodu (v. §2); izbačen GeoIP/ASN (novi dependency bez jasne vrijednosti).
> 5. Biblioteka `@simplewebauthn/*` na **v14** (Node 22+, a CI je na 22), postavke kao **skalarni ključevi** (5.3.4 registry pattern, ne JSON blob), E2E preko **Playwright Virtual Authenticator-a**, nazivi migracija u postojećem `2027xxxx` stilu.

## 1. Cilj

Paketi 2.1 i 5.2.1 isporučili su osnovni sigurnosni sloj: TOTP MFA, registar sesija, odvojeni account/IP rate-limit bucketi, HMAC-pseudonimizirane ključeve u Redisu, opoziv recovery code-a po upotrebi. Preostale sigurnosne stavke koje su svjesno odgođene iz opsega 5.2 spadaju u četiri grupe i zajedno čine **5.4 security hardening**:

1. **Phishing-otporan MFA (WebAuthn / passkey):** dodati FIDO2 / passkey kao drugi faktor, pored postojećeg TOTP-a, uključujući i potvrdu osjetljivih akcija (step-up).
2. **Konfigurabilni i mjerljivi rate limit:** pragovi danas hardkodirani, nema adminu vidljive metrike — prebaciti u konfiguraciju i dodati graf/alert.
3. **Politička proširenja (CAPTCHA, "remember me", idle timeout):** kada limiti nisu dovoljni, i kada korisnik želi ostati prijavljen.
4. **Prijava i admin opcije:** HIBP provjera lozinki, prisilna promjena lozinke za sve lokalne korisnike, dopuna sigurnosnog dnevnika (audit log) i prikaz za admine.

## 3. Odluke dizajna

### M1: Phishing-otporan drugi faktor (WebAuthn / FIDO2 / passkey)

- **Biblioteka:** `@simplewebauthn/server` **^14** (server) i `@simplewebauthn/browser` **^14** (klijent). CI je na Node 22, a v14 traži Node LTS 22+ — usklađeno. Pri instalaciji provjeriti breaking changes v10→v14 (API potpisi, `requireUserVerification`, WebCrypto-only).
- **Tip faktora:** `userVerification: "preferred"` za login; **`required`** za step-up potvrdu osjetljivih akcija. Podržavamo **platform authenticator** (Windows Hello / Touch ID / Face ID) i **cross-platform authenticator** (YubiKey i sl.).
- **Način skladištenja:** nova tabela `UserPasskeyCredential` (povezana na `User`):
  - `id` (cuid)
  - `userId` FK → User
  - `credentialId` (base64url, unique)
  - `publicKey` (base64url COSE, `VarChar(1024)`) — v13+ API vraća COSE bajtove; konverzija u JWK ne donosi vrijednost *(dopuna revizije: bilo `publicKeyJwk` jsonb)*
  - `counter` (bigint, za cloned-key detekciju)
  - `transports` (csv string, npr. `internal,nfc`)
  - `aaguid` (text, za prikaz vrste ključa u UI: "YubiKey 5", "Windows Hello")
  - `deviceName` (korisnički string, npr. "Moj YubiKey kod kuće")
  - `createdAt`, `lastUsedAt`, `lastUsedIp`
  - `isBackupEligible`, `isBackedUp` (za obavijest "vaš ključ je sinkroniziran u cloud")
- **Tok prijave:** nastavljamo postojeći pattern "međukoraka":
  1. `POST /auth/login` → vraća `{ status: 'MFA_REQUIRED', mfaToken, methods: ['totp','passkey'] }` — `methods` je novo polje; stari klijenti ga ignoriraju (backward compatible), a frontend mora podnijeti i njegovo odsustvo.
  2. Ako korisnik izabere passkey: `POST /auth/mfa/passkey/start (mfaToken)` → vraća `options` (WebAuthn `authenticationOptionsJSON`).
  3. Browser odradi `startAuthentication()` iz `@simplewebauthn/browser` → dobiva `assertion`.
  4. `POST /auth/mfa/passkey/verify (mfaToken, assertion)` → validira (userHandle → korisnik, counter monotono raste, cloned-key → blokada faktora), izdaje `accessToken`.
  5. TOTP i recovery code ostaju fallback (korisnik bez passkeyja ili izgubljen uređaj).
- **Step-up potvrda osjetljivih akcija (novo u reviziji):** identity-guard pored TOTP koda prihvaća i **passkey assertion**:
  1. `POST /security/identity/passkey/start (purpose)` — sesija-autentificiran; izdaje WebAuthn options s `userVerification: 'required'` i short-lived challenge u Redisu (`identity-challenge:<sessionId>:<purpose>`, TTL ~2 min).
  2. `POST /security/identity/passkey/verify (purpose, assertion)` — validira assertion protiv kredencijala prijavljenog korisnika; uspjeh postavlja isti "svježa potvrda" marker koji danas postavlja TOTP put (`privacy-identity-confirmer.ts` dobija drugi potvrđeni `method: 'passkey'`).
  3. postojeći `MfaCodeForm` dijalog dobija tab/passkey-duže "Potvrdi passkeyjem" kad korisnik ima passkey kredencijale.
- **Registracija:** u "Moj profil → Sigurnost → Dodaj passkey". Kad je TOTP već upisan, confirm zahtijeva važeći TOTP kod (ukradena sesija sama ne smije dodati faktor); kad je passkey prvi faktor računa, sama attestation (posjed uređaja) je dokaz — usklađeno s postojećim TOTP upisom. Registracija snima `transports` i `aaguid` iz attestation odgovora.
- **Recovery:** postojeći recovery codes rade za oba faktora (recovery code jednokratan, neovisno da li je inače korišten TOTP ili passkey).
- **Pravila:**
  - **SUPER_ADMIN** uvijek mora imati najmanje jedan MFA faktor (TOTP i/ili passkey); brisanje posljednjeg faktora je zabranjeno (409).
  - Passkey se ne postavlja kao "jedini faktor" za sada (phishing-otporan, ali riskira account lockout ako korisnik izgubi sve uređaje); admin policy u admin settingsu može podesiti `requiredMfaMethods` (rezervisano za kasnije, ne 5.4.0).
- **Entra korisnici:** ne koriste naš MFA — njihova phishing-otpornost je stvar Conditional Access politike u Entra-u (ostaviti kako je).

### M2: Konfigurabilni rate limit i admin metrika

- **Izvor konfiguracije:** **skalarni ključevi** u 5.3.4 settings registry-ju (po ključu bs/en `title`/`help` i `requires`-uslovi, kao CSAT/Teams definicije — ne jedan JSON blob):
  - `private.security.rateLimits.passwordLogin.accountWindowSeconds` (1800)
  - `private.security.rateLimits.passwordLogin.accountDelayStartsAfterFailures` (3)
  - `private.security.rateLimits.passwordLogin.accountDelayBaseMilliseconds` (250)
  - `private.security.rateLimits.passwordLogin.accountDelayMaxMilliseconds` (2000)
  - `private.security.rateLimits.passwordLogin.ipMaxFailures` (40)
  - `private.security.rateLimits.passwordLogin.ipWindowSeconds` (300)
  - `private.security.rateLimits.other.maxFailures` (5), `private.security.rateLimits.other.windowSeconds` (900) — za Entra/promjenu lozinke/MFA
  - defaulti u definicijama postavki = današnje konstante; `LoginAttemptLimiter` i memoriski store (`createMemoryLoginAttemptStore`) čitaju vrijednosti kroz isti loader (mockabilno u testovima).
- **Admin panel:** "Postavke → Sigurnost → Ograničenja prijava" — forma od 8 skalarnih polja; `PUT /security/rate-limits` upisuje sve ključeve **kroz `setSettingValues` u jednoj transakciji s jednim razlogom** (isti obrazac kao notice-editor), uz obaveznu MFA potvrdu (TOTP ili passkey step-up).
- **Verifikacija pri čuvanju:** odbiti vrijednosti koje značajno slabe zaštitu (npr. `ipMaxFailures > 500`, `windowSeconds < 10`); granice u loader-validaciji i na admin formi.
- **Efekt bez restarta:** limiter čita konfiguraciju po zahtjevu (cache unutar tick-a); promjena vrijedi odmah.
- **Metrika:**
  - interni brojači u Redisu, 1-hour vremenske serije po minuti:
    - `security:metrics:login-429:<minuteBucket>` (IP bucket)
    - `security:metrics:login-account-delays:<minuteBucket>`
    - `security:metrics:mfa-failures:<minuteBucket>`
  - Admin endpoint `GET /security/metrics/last-hour` (SUPER_ADMIN) agregira i **ne vraća PII**; mali graf na Admin → Nadzor.
  - Alarm (postojeći alarm/DLQ sistem) kad satna stopa 429 pređe prag (default 50) — indikator brute-force napada; runbook `docs/ops/rate-limits.md` dopunjen.

### M3: CAPTCHA / Turnstile (odloženo, ali projektovano)

- Ne ulazi u 5.4.0 — **ekstenzijska tačka**: `LoginAttemptLimiter` ima plug-in interface `CaptchaChallenge` koji se poziva nakon N (npr. 5) uzastopnih grešaka ili nakon prvog 429 na IP razini.
- Preporučeni provajder: Cloudflare Turnstile (besplatan, lakši za self-host od reCAPTCHA).
- Kad se bude uvodio (5.4.1): skalarni ključevi `private.security.captcha.provider` (`'none' | 'turnstile'`) + `siteKey`/`secretKey` (secret ide u private postavke); kad nije konfigurirano, ponašanje je isto kao danas.

### M4: Politika sesija i "remember me" (suženo u reviziji)

- Device info, `lastSeenAt`, detekcija novog uređaja i `accountNewDevice` obavijest **već postoje** — ništa se ne gradi; pri implementaciji samo provjeriti da profilna lista sesija prikazuje uređaj (ip/userAgent su u API odgovoru). GeoIP/ASN se **ne uvodi**.
- **"Remember me" checkbox na login formi** (off po defaultu; za SUPER_ADMIN sakriven i ignorisan — break-glass nalog mora biti kratkotrajna sesija):
  - kada je uključen, session TTL je **30 dana** (umjesto 60 min), uz klizni refresh pri `/auth/refresh`;
  - dugotrajne sesije se mogu odjaviti iz "Moj profil → Aktivne sesije" i iz admin pregleda (postojeće funkcije).
- **Idle timeout:** skalarna postavka `private.security.session.idleTimeoutSeconds` (0 = isključeno, default). **Enforcement je server-side:** pri `/auth/refresh` ako `now - lastSeenAt > idleTimeout` → revoke sesije + 401 (klijentski logout nije enforce). Vrijednost `0` znači "isključeno" i ne smije se pomiješati sa "bez timeouta".

### M5: Password politika i bulk akcije (suženo u reviziji)

- **HIBP provjera lozinke — uključena po defaultu (odluka vlasnika 2026-10-09):**
  - pri promjeni lozinke i admin resetu: k-anonymity upit ka `api.pwnedpasswords.com/range/p<prvi5Hex>` i odbiti lozinku čiji SHA-1 sufiks se pojavljuje u breach-ovima;
  - **cache odgovora po prefixu u Redisu 24 h**;
  - **timeout 3 s i fail-open**: ako mreža nije dostupna ili poziv padne, lozinka se prihvati uz `warn` log i brojač `security:metrics:hibp-skipped:<minuteBucket>` (offline self-host ne smije biti blokiran od promjene lozinke);
  - admin toggle `private.security.hibp.enabled` (default `true`) u "Postavke → Sigurnost"; status provjere vidljiv uz poruku greške forme kad je odbijena.
- **Prisilna promjena lozinke za sve lokalne korisnike:** admin dugme u "Postavke → Sigurnost":
  - koristi postojeću kolonu `mustChangePassword` (postoji) — postavlja se svim lokalnim korisnicima **osim SUPER_ADMIN-a**;
  - poništava sve aktivne sesije lokalnih naloga (kao reset-password put);
  - koristi postojeći mehanizam privremene lozinke / postavljanja nove pri sljedećoj prijavi;
  - Entra korisnici se ne diraju (lozinku vodi Entra).
- **Istek lozinke:** već je izračunat iz `passwordChangedAt` + politika (`passwordMaxAgeDays` / `superAdminPasswordMaxAgeDays`) — **bez nove kolone**; dodati samo upozorenje 7 dana prije isteka i prisilan redirect na `/change-password` kad istekne (provjeriti postojeći redirect prije dupliranja).

### M6: Sigurnosni dnevnik — proširenje postojećeg audit loga (odluka vlasnika)

- **Bez nove `SecurityEvent` tabele.** Događaji se zapisuju u postojeći audit log, koji već ima `auth.mfa_enrolled/disabled/reset/failed`, `auth.mfa_recovery_used/regenerated`, `auth.password_changed/expired`. Dopuniti akcije:
  - `auth.login_failed` (pseudonimiziran account/IP ključ — isti HMAC pristup kao rate-limit ključevi; **bez** pseudonimiranog e-maila u sadržaju),
  - `auth.mfa_passkey_enrolled`, `auth.mfa_passkey_removed`,
  - `auth.session_revoked`, `auth.session_revoked_all`,
  - `auth.password_reset_must_change`, `auth.admin_bulk_password_reset`,
  - `auth.admin_rate_limits_changed`.
  - Usupješne prijave se **ne** loguju pojedinačno (volumen); samo neuspjehe i admin/sigurnosno-relevantne akcije.
- **Admin prikaz:** "Sigurnost → Dnevnik" — **filtrirani pogled na postojeći audit log** (kategorija `auth.*`) s paginacijom i filterom po korisniku/akciji; retencija se **ne** uvodi posebno — nasljeđuje postojeću audit-log retenciju iz privatnost modula.
- **Opciona extradа (webhook/syslog)** — dizajn bilježi tačku, ostavlja se za 5.4.1/kasnije.

## 6. Frontend

- **Moj profil → Sigurnost:** kartica "Passkey" pored "Aplikacija (TOTP)" i "Recovery kodovi"; lista registrovanih passkeyja (naziv, vrsta po `aaguid`, `createdAt`, `lastUsedAt`, backup zastavica) s "Preimenuj" i "Ukloni"; dugme "Dodaj passkey" (traži potvrdu identiteta).
- **Login stranica → MFA korak:** izbor metode (`methods` iz login odgovora; default zadnje korištena metoda) — "Kod iz aplikacije" ili "Koristi passkey / uređaj".
- **Potvrda osjetljivih akcija (MfaCodeForm dijalog):** dodatna opcija "Potvrdi passkeyjem" kad korisnik ima kredencijale (step-up tok).
- **Admin → Postavke → Sigurnost:** kartica "Ograničenja prijava" (8 skalarnih polja + razlog + MFA potvrda), "Politika sesija" ("remember me" napomena + idle timeout), "HIBP provjera lozinki" (toggle), "Prisilna promjena svih lozinki" (dugme s potvrdom).
- **Admin → Nadzor:** mali graf "Promašene prijave / 429" (posljednji sat/dan) uz postojeći monitoring.
- **Admin → Sigurnost → Dnevnik:** filtrirani pogled na audit log (`auth.*`) s paginacijom i filterima.
- Sve nove kontrole kroz Pulse design system (token-bound radijus, bez `rounded-xl`), `title`/`help` stringovi bs+en, a11y provjera (`node scripts/check-a11y-static.mjs`).

## 8. Ograničenja / ne radi se u 5.4

- **Ne uvodimo SMS/e-mail MFA** — ostaje TOTP + passkey + recovery code (SMS je sam po sebi nesiguran faktor).
- **Ne uvodimo SAML/OIDC providera za SSO** u ovom paketu (Entra je danas dovoljan; generalni SSO je veći, odvojen paket).
- **Ne uvodimo password-less login bez lozinke** (passkey ostaje *drugi* faktor u 5.4; bez-lozinke je poseban dizajn).
- **Ne uvodimo HSM za JWT secret** — JWT secret ostaje u env varijabli (operativni hardening, kasniji paket).
- **Ne uvodimo GeoIP/ASN** detekciju (novi dependency; device info i obavijest o novom uređaju već postoje).
- **CAPTCHA/Turnstile integracija** se samo projektuje (M3), ne isporučuje u 5.4.0 — ide u 5.4.1 (čeka odluku o provajderu; Turnstile preporuka).
- **Webhook/syslog extradа sigurnosnog dnevnika** — dizajn bilježi tačku, ne isporučuje se u 5.4.0.

## 10. Zavisnosti i polazne osnove

- Biblioteke: `@simplewebauthn/server` ^14, `@simplewebauthn/browser` ^14 (Node LTS 22+ — CI je na 22; provjeriti breaking changes prije instalacije).
- RP ID i RP name se čitaju iz konfiguracije (`PUBLIC_ORIGIN` host za produkciju; `localhost` za development) — iznaći opcionu env varijablu `WEBAUTHN_RP_ID` samo ako hosting zahtijeva odvojen RP ID.
- Redis je već dependency (rate-limit i revokacija) — novi ključevi (metrike, identity-challenge) u istu instancu.
- `createMemoryLoginAttemptStore` se proširuje da čita konfiguraciju iz postavki (ne iz hardkodiranih konstanti) radi mockanja u testovima.
- HIBP zahtijeva odlazak na internet sa servera; kad mreža nije dostupna → fail-open + log + metrika (v. M5). Nije potrebna ključ/aplikanca (k-anonymity range API je otvoren).
- Prisma blokada u sandboxu ostaje: backend `tsc`/`build` se verifikuju na korisnikovom serveru; lokalno jedinčni testovi kroz vitest/jest sa mockovima.

## 11. Kriterij prihvaćanja

- [ ] Korisnik može registrovati barem jedan passkey u svom profilu (uz potvrdu identiteta) i prijavljivati se njime (bez TOTP-a).
- [ ] TOTP i recovery code ostaju funkcionalni kao što su bili; `methods` polje u login odgovoru je backward compatible.
- [ ] Brisanje posljednjeg MFA faktora je zabranjeno (SUPER_ADMIN uvijek ima najmanje jedan faktor).
- [ ] Potvrda osjetljive akcije (npr. privatnost izvoz) prolazi passkey assertion-om (`userVerification: required`).
- [ ] Admin može podesiti rate-limit pragove kroz UI (batch, s razlogom i MFA potvrdom); efekt je vidljiv bez restarta; vrijednosti van granica se odbijaju.
- [ ] Admin vidi agregirani graf 429/delay/MFA grešaka u Nadzoru; alarm se okida na prag 429/h.
- [ ] "Remember me" produžava sesiju na 30 dana; za SUPER_ADMIN nije dostupan i ignorisan je server-side.
- [ ] Idle timeout (kad je uključen) revokuje sesiju pri `/auth/refresh` nakon neaktivnosti; default isključen.
- [ ] Promjena lozinke provjerava HIBP (default ON; cache 24 h; timeout 3 s; fail-open uz log i metriku kad mreže nema) i odbija procurile lozinke.
- [ ] "Prisilna promjena svih lozinki" prekida sesije lokalnih korisnika i nameće `mustChangePassword` (osim SUPER_ADMIN i Entra naloga).
- [ ] Sigurnosni dnevnik prikazuje `auth.*` događaje uključujući nove akcije (login_failed pseudonimiziran, passkey enrolled/removed, session revoked, bulk reset, rate-limits changed) u admin prikazu; retencija nasljeđuje postojeću audit-log retenciju.
- [ ] E2E 46 (passkey, Virtual Authenticator) i 47 (rate-limits konfiguracija) zeleni na serveru; 37 proširen i zelen.
- [ ] `docs/ops/rate-limits.md` ažuriran (konfigurabilni pragovi, put do admin panela, runbook alarma); korisnički vodiči i `sta-je-novo.md` dopunjeni uz closeout vala.
