# Paket 5.4: Sigurnosni hardening (phishing-otporan MFA, konfigurabilni limiti, CAPTCHA, politika sesija)

> Status: **dizajn / čeka odobrenje** · Procjena: ~5–6 RD · Izvor: REVIEW_ANALIZA 5.2.4 closeout (preostale sigurnosne stavke), RAW §29 (SuperAdmin lokalni-only), §20 (revizija pristupa), §M2 iz 2026-10-02 dependency/MFA/rollback reviewa, dopuna nakon vlasnikove odluke (2026-10-08: "definitivno dizajn za 5.4")

## 1. Cilj

Paketi 2.1 i 5.2.1 isporučili su osnovni sigurnosni sloj:
TOTP MFA, registar sesija, odvojeni account/IP rate-limit bucketi, HMAC-pseudonimizirane ključeve u Redisu, opoziv recovery code-a po upotrebi. Preostale sigurnosne stavke koje su svjesno odgođene iz opsega 5.2 spadaju u četiri grupe i zajedno čine **5.4 security hardening**:

1. **Phishing-otporan MFA (WebAuthn / passkey):** dodati FIDO2 / passkey kao drugi faktor, pored postojećeg TOTP-a.
2. **Konfigurabilni i mjerljivi rate limit:** pragovi danas hardkodirani, nema adminu vidljive metrike — prebaciti u konfiguraciju i dodati graf/alert.
3. **Politička proširenja (CAPTCHA, "remember me", session TTL politike):** kada limiti nisu dovoljni, i kada korisnik želi ostati prijavljen.
4. **Prijava i admin opcije:** vidljivost sigurnosnih događaja, prisilna promjena lozinke za sve korisnike, opoziv svih sesija pri sumnji na proboj.

## 3. Odluke dizajna

### M1: Phishing-otporan drugi faktor (WebAuthn / FIDO2 / passkey)

- **Biblioteka:** koristiti `@simplewebauthn/server` (server) i `@simplewebauthn/browser` (klijent) — standardna, TypeScript-prijateljska biblioteka bez native dependency-a.
- **Tip faktora:** `userVerification: "preferred"` (passkey podržava i biometriju i ekran-lock); za početak podržavamo **platform authenticator** (Windows Hello / Touch ID / Face ID) i **cross-platform authenticator** (YubiKey i sl.).
- **Način skladištenja:** nova tabela `UserPasskeyCredential` (povezana na `User`):
  - `id` (cuid)
  - `userId` FK → User
  - `credentialId` (base64url, unique)
  - `publicKeyJwk` (jsonb)
  - `counter` (bigint, za cloned-key detekciju)
  - `transports` (text[], npr. `["usb","nfc","ble","internal"]`)
  - `aaguid` (text, za prikaz vrste ključa u UI: "YubiKey 5", "Windows Hello")
  - `deviceName` (korisnički string, npr. "Moj YubiKey kod kuće")
  - `createdAt`, `lastUsedAt`, `lastUsedIp`
  - `isBackupEligible`, `isBackedUp` (za obavijest "vaš ključ je sinkroniziran u cloud")
- **Tok prijave:** Nastavljamo postojeći pattern "međukoraka":
  1. `POST /auth/login` → vraća `{ status: 'MFA_REQUIRED', mfaToken, methods: ['totp','passkey'] }`.
  2. Ako korisnik izabere passkey: `POST /auth/mfa/passkey/start (mfaToken)` → vraća `options` (WebAuthn `authenticationOptionsJSON`).
  3. Browser odradi `startAuthentication()` iz `@simplewebauthn/browser` → dobiva `assertion`.
  4. `POST /auth/mfa/passkey/verify (mfaToken, assertion)` → validira, izdaje `accessToken`.
  5. TOTP ostaje kao fallback (korisnik bez passkeyja ili izgubljen uređaj i dalje koristi TOTP ili recovery code).
- **Registracija:** u "Moj profil → Sigurnost → Dodaj passkey". Zaštiti se trenutnim MFA kodom ili novom passkey potvrdom.
- **Recovery:** postojeći recovery codes rade za oba faktora (recovery code jednokratan, neovisno da li je inače korišten TOTP ili passkey).
- **Pravila:**
  - **SUPER_ADMIN** uvijek mora imati najmanje jedan MFA faktor (TOTP i/ili passkey).
  - Passkey se ne postavlja kao "jedini faktor" za sada (phishing-otporan, ali riskira account lockout ako korisnik izgubi sve uređaje); admin policy u admin settingsu može podesiti `requiredMfaMethods`.
- **Entra korisnici:** ne koriste naš MFA — njihova phishing-otpornost je stvar Conditional Access politike u Entra-u (ostaviti kako je).

### M2: Konfigurabilni rate limit i admin metrika

- **Izvor konfiguracije:** `private.security.rateLimits.*` JSON u `system_configuration` (postojeći loader pattern kao za CSAT, Teams, SLA). Admin panel: "Postavke → Sigurnost → Ograničenja prijava".
- **Polja (sa defaultima = današnje vrijednosti):**
  - `passwordLogin.accountWindowSeconds` (1800)
  - `passwordLogin.accountDelayStartsAfterFailures` (3)
  - `passwordLogin.accountDelayBaseMilliseconds` (250)
  - `passwordLogin.accountDelayMaxMilliseconds` (2000)
  - `passwordLogin.ipMaxFailures` (40)
  - `passwordLogin.ipWindowSeconds` (300)
  - `other.maxFailures` (5), `other.windowSeconds` (900) — za Entra/promjenu lozinke/MFA
- **Verifikacija pri čuvanju:** admin ne smije unijeti vrijednosti koje bi značajno oslabile zaštitu (npr. ipMaxFailures > 500, window < 10 s); dati potvrdu drugog faktora pri mijenjanju.
- **Metrika:**
  - Dodati interni brojač u `LoginAttemptLimiter` (i `mfa.service.ts` za MFA) koji u Redis drži 1-hour vremenske serije po ključu:
    - `security:metrics:login-429:<minuteBucket>` (IP bucket)
    - `security:metrics:login-account-delays:<minuteBucket>`
    - `security:metrics:mfa-failures:<minuteBucket>`
  - Admin endpoint `GET /security/metrics/last-hour` koji agregira (ne vraća PII), i mali graf na Admin → Nadzor (21 dan trend).
  - Alarm (koristeći postojeći alarm/DLQ sistem) kada satna stopa 429 pređe npr. 50 — indikator brute-force napada.

### M3: CAPTCHA / Turnstile (odloživ, ali projektovati)

- Ne ulazi u prvi val 5.4.0, ali **ostaviti ekstenzijsku tačku** — `LoginAttemptLimiter` će imati plug-in interface `CaptchaChallenge` koji se poziva nakon N (npr. 5) uzastopnih grešaka ili nakon prvog 429 na IP razini.
- Preporučeni provajder: Cloudflare Turnstile (besplatan, pristupačniji od reCAPTCHA, lak za self-host scenarija).
- Podesivo kroz `private.security.captcha.provider = 'none' | 'turnstile'` + `siteKey`/`secretKey`.
- Kad nije konfigurirano, ponašanje je isto kao danas (delay + 429).

### M4: Politika sesija i "remember me"

- **"Remember me" checkbox na login formi** (opcionalno, off po defaultu i za SUPER_ADMIN je ignorisan):
  - kada je uključen, session TTL je **30 dana** (umjesto 60 min), uz klizni refresh dok je korisnik aktivan (postavlja novi exp sa svakim `/auth/refresh`);
  - dugotrajne sesije se mogu odjaviti iz "Moj profil → Aktivne sesije" i iz admin pregleda;
  - SUPER_ADMIN nikad nema "remember me" (break-glass nalog mora biti kratkotrajna sesija).
- **Idle timeout:** konfigurabilna opcija u admin settingsima (default isključeno) — npr. "nakon 30 min neaktivnosti izloguj korisnika".
- **Device fingerprint/risky sign-in:** za 5.4.0 bilježiti `userAgent`, `ip`, `asn` (ili country) pri izdavanju sesije i prikazivati u listi aktivnih sesija (postojeća lista je danas ID-only, koliko se sjećam — provjeriti); obavijest korisniku na e-mail kad se sesija otvori iz nove kombinacije (opcionalno, može se isključiti). Ovo je jednostavna varijanta detekcije rizičnih prijava.

### M5: Password politika i bulk akcije

- **HIBP provjera lozinke:** pri promjeni lozinke i pri admin resetu, pozvati k-anonimity HIBP API i odbiti lozinku koja se pojavljuje u poznatim breach-ovima. Cache odgovora (po prefixu hasha) u Redisu 24h.
- **Prisilna promjena lozinke za sve lokalne korisnike:** admin dugme u "Postavke → Sigurnost" koje:
  - poništava sve aktivne sesije svih lokalnih naloga (kao reset-password);
  - svim lokalnim korisnicima postavlja `mustChangePassword = true` (osim SUPER_ADMIN — on se mora ručno opozvati);
  - šalje postojeći mehanizam privremene lozinke ili traži od korisnika da postavi novu pri sljedećoj prijavi.
- **Istek lozinke za SUPER_ADMIN:** postoji već (`passwordExpiresAt`), dodati upozorenje 7 dana prije isteka i prisilan redirect na `/change-password` kad istekne.

### M6: Security audit log

- Proširiti postojeći notification sistem u **uniformni sigurnosni event stream**:
  - `auth.login.success`, `auth.login.failure` (sa anonimiziranim account/IP ključevima),
  - `auth.mfa.enabled`, `auth.mfa.disabled`, `auth.mfa.passkey.added`, `auth.mfa.passkey.removed`,
  - `auth.password.changed`, `auth.password.reset_by_admin`, `auth.password.reset_must_change`,
  - `auth.session.revoked`, `auth.session.revoked_all`,
  - `auth.rate_limit.triggered` (anonimizirano),
  - `auth.admin.bulk_password_reset`, `auth.admin.rate_limits_changed`.
- Dogadjaji se zapisuju u novu tabelu `SecurityEvent` (slično `TicketActivity`) i prikazuju u admin panelu "Sigurnost → Dnevnik".
- Za self-host: opcija da se ovi event-i šalju na syslog/webhook (kao i alarmi iz postojećeg DLQ/alarm sistema).

## 4. Struktura podataka

Nove migracije:

1. `20261020000000_add_user_passkey_credential.ts` — tabela `UserPasskeyCredential` sa FK i indeksima (`credentialId` unique, `userId` indeks).
2. `20261020000001_security_event.ts` — tabela `SecurityEvent` (id, createdAt, actorUserId?, eventType, targetUserId?, ipHash?, details jsonb); gledaj da se PII (IP) hešira kao i rate-limit ključevi.
3. Dodati `private.security.rateLimits`, `private.security.captcha`, `private.security.session` u sistem configuration šemu.

## 6. Frontend

- **Moj profil → Sigurnost:** nova kartica "Passkey" pored "Aplikacija (TOTP)" i "Recovery kodovi"; lista registrovanih passkeyja sa opcijama "Preimenuj" i "Ukloni"; dugme "Dodaj passkey".
- **Login stranica → MFA korak:** izbor metode (TOTP kod ili "Koristi passkey / uređaj") — ponovo kroz selektor kao danas jedan MFA form; default je zadnje korištena metoda.
- **Admin → Postavke → Sigurnost:** kartica "Ograničenja prijava" (konfiguracija pragova i CAPTCHA), "Politika sesija" ("remember me" i idle timeout), "Dnevnik događaja" (SecurityEvent tabela).
- **Admin → Nadzor:** dodatak malog grafa "Promašene prijave / 429" uz postojeći monitoring.

## 8. Ograničenja / ne radi se u 5.4

- **Ne uvodimo SMS/e-mail MFA** — ostaje TOTP + passkey + recovery code (SMS je sam po sebi nesiguran faktor).
- **Ne uvodimo SAML/OIDC providera za SSO** u ovom paketu (Entra je danas dovoljan; budući da je generalni SSO priča veći paket odvojen od sigurnosnog hardeninga).
- **Ne uvodimo password-less login bez lozinke** (passkey ostaje *drugi* faktor u 5.4; potpuno bez-lozinke je veći zahvat i poseban dizajn).
- **Ne uvodimo hardware security module (HSM) za JWT secret** — JWT secret ostaje u env varijabli; ovo je tema operativnog hardeninga za poseban 5.5/6.x paket.
- **CAPTCHA/Turnstile integracija** se samo projektnuje (M3), ne isporučuje u 5.4.0 — ide u 5.4.1.

## 10. Zavisnosti i polazne osnove

- Biblioteka: `@simplewebauthn/server` ^10.x, `@simplewebauthn/browser` ^10.x (provjeriti aktuelnu stabilnu verziju u vrijeme implementacije).
- RP ID (`WEBAUTHN_RP_ID`) i RP Name se čitaju iz konfiguracije (env `PUBLIC_ORIGIN` za produkciju; za development `localhost`).
- Redis je već dependency (koristi se za rate-limit i revokaciju) — dodati nove ključeve u istu instancu.
- Postojeći testni auth store (`createMemoryLoginAttemptStore`) treba se proširiti da čita konfiguraciju iz `private.security.rateLimits.*` (ne iz hardkodiranih konstanti) kako bi se vrijednosti mogle mockati u testovima.

## 11. Kriterij prihvaćanja

- [ ] Korisnik može registrovati barem jedan passkey u svom profilu i potom se prijavljivati koristeći ga (bez TOTP-a).
- [ ] TOTP i recovery code ostaju funkcionalni kao što su bili.
- [ ] Za račun koji ima passkey uklanjanje posljednjeg MFA faktora je zabranjeno (SUPER_ADMIN uvijek ima najmanje jedan).
- [ ] Admin može podesiti rate-limit pragove kroz UI, efekt je vidljiv bez restarta.
- [ ] Admin vidi agregiran graf 429/delay/MFA grešaka u posljednjih sat/dan u Nadzoru.
- [ ] "Remember me" produžava sesiju za 30 dana; nije dostupno za SUPER_ADMIN.
- [ ] Promjena lozinke provjerava HIBP (online, sa cacheom) i ne dozvoljava već procurile lozinke.
- [ ] Dugme "Prisili promjenu svih lozinki" prekida sve sesije i nameće `mustChangePassword`.
- [ ] Security event log bilježi sve akcije iz M6 i dostupan je kroz admin UI.
- [ ] E2E testovi pokrivaju barem happy-path passkey registracija/login, konfiguraciju limita i bulk reset.
- [ ] Dokument `docs/ops/rate-limits.md` ažuriran s novim opcijama i putem do admin panela.
