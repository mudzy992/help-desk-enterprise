## API facade split

Javni import putevi ostali su kompatibilni:

- `@/services/problems-api`;
- `@/services/changes-api`.

Facade moduli re-exportuju izdvojene domenske implementacije:

- `services/problems-api/links.ts` — asset/service/incident veze i reference;
- `services/changes-api/calendar-templates.ts` — calendar, template i related-record operacije.

Nisu promijenjeni endpointi, request bodyji, query ključevi niti javni DTO tipovi.

## Problems i Changes list modeli

URL status/filter pravila izdvojena su u čiste modele:

- `lib/problems/problem-list-filters.ts`;
- `lib/changes/change-list-filters.ts`.

Zajednička immutable izmjena search parametra je u `lib/entity-list/with-search-param.ts`. Pages i dalje posjeduju query orkestraciju, partial-resource/error prikaz, paging i dialog lifecycle.

Direktni testovi potvrđuju:

- fallback nepoznatog URL statusa na `open`;
- `all` bez status ograničenja;
- pojedinačni status;
- odbacivanje nepoznatog change type/risk filtera.

## Template i playbook editor split

Izdvojeno je:

- `components/templates/playbook-steps-editor.tsx` — step prikaz, drag/drop, keyboard move, add/remove i povezani article/template izbori;
- `lib/templates/playbook-editor-model.ts` — stabilni draft identitet, blank step i zadržavanje trenutno odabrane scope opcije;
- `lib/templates/response-template-editor-model.ts` — forma, početne vrijednosti i body-field ugovor;
- `components/templates/template-scope-cell.tsx` — scope summary prikaz;
- `lib/templates/editor-lifecycle.ts` — imenovani loading/ready/saving/error lifecycle i unsaved-navigation policy.

Editor pageovi zadržavaju load/save side effecte, live refresh, API error mapping, permissions i route navigaciju. Poslovna logika nije premještena u generički UI folder.
