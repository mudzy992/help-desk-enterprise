## Razdvojena dva tipa dokaza

Implementacija više ne tretira production React `<Profiler>` callback kao garantovan dokaz. Izričito su razdvojeni:

1. **production build** — browser long-task mjerenje;
2. **react-profiling build** — React commit/rerender mjerenje i long-task mjerenje.

Oba ostaju opt-in preko `?profile=1`.

## Izolovani profiling build

Dodan je script:

```text
npm run build:profiling
```

Script koristi Vite mode `react-profiling` i zasebni output `dist-profiling`. Samo taj mode aliasira:

- `react-dom` na `react-dom/profiling`;
- `react-dom/client` na `react-dom/profiling`.

Default `npm run build` ne aktivira te aliase. Oba builda koriste isti source, TypeScript build, Vite konfiguraciju, minifikaciju i aplikacijsku konfiguraciju.

Compile-time marker je:

- `buildKind: production` za default build;
- `buildKind: react-profiling` za profiling build.

Direktna inspekcija build izlaza potvrđuje:

- default `dist/static` ne sadrži `react-profiling` marker;
- zasebni `dist-profiling/static` sadrži marker;
- profiling output se ne koristi kao default produkcijski artefakt.

## Runtime report

`window.__EPHD_PROFILE__` sada ima eksplicitni JSON-kompatibilni ugovor:

- `buildKind`;
- broj commitova;
- ukupno i maksimalno React commit trajanje;
- ograničeni commit sampleovi;
- long-task sampleovi;
- ukupno i maksimalno long-task trajanje.

Long-task observer:

- aktivira se samo uz `?profile=1`;
- provjerava browser podršku za `longtask` entry;
- koristi buffered observer;
- prekida observer pri unmountu;
- ograničava sample listu na 500 zapisa.

Production rezultat smije koristiti long-task polja, ali ne smije tvrditi da je izmjerio React commit kada je `commits === 0`. Profiling rezultat mora imati `buildKind: react-profiling` i više od nula commitova prije 10/10 tvrdnje.

## Zaključani pragovi

Machine-readable pragovi su u:

- `docs/frontend/quality/performance-thresholds.json`.

Zaključani su prije daljnje optimizacije:

- maksimalan broj commitova;
- maksimalni pojedinačni commit;
- ukupno commit trajanje;
- maksimalan broj long taskova;
- ukupno i pojedinačno long-task trajanje;
- cold/warm metodologija;
- browser i runner klasa;
- fixture cardinality po scenariju;
- owner `frontend-platform`;
- datum revizije 22.01.2027.

Scenariji:

1. dashboard;
2. ticket list;
3. ticket inbox;
4. ticket detail;
5. Assets veliki skup;
6. service catalog veliki skup.

## Regresijski guard

`profiling-build-contract.spec.ts` potvrđuje:

- profiling script koristi zasebni Vite mode;
- default build script ne koristi profiling mode;
- aliasi postoje samo iza mode uslova;
- production i profiling evidence ugovori nisu pomiješani;
- commit pragovi su pozitivni;
- svaki scenario koristi `profile=1` i zapisanu pozitivnu fixture cardinality;
- owner i review datum postoje.

## Ocjena dokaza

Kod i build infrastruktura za pravi React profiling dokaz sada postoje. Lokalni sandbox nema završni autentifikovani browser/performance runner i zato se ovdje ne iznosi lažna tvrdnja o broju commitova. Stvarni `>0` commit i threshold rezultat ulazi u jedini postojeći finalni CI dokaz `OPEN-CI-FINAL`; ne uvodi se druga korisnička obaveza.

Do tog artefakta performance kriterij podržava najviše **9,9**, ne 10/10. Nakon zelenog profiling rezultata sa `buildKind: react-profiling`, `commits > 0` i zelenim pragovima, performance kriterij može biti 10/10.
