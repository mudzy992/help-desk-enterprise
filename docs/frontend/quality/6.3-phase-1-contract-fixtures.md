# Paket 6.3 — Faza 1: cross-layer API contract fixtures

## Status

- **Datum:** 22.10.2026.
- **Nalaz:** FA1
- **Status:** zatvoren
- **Shared fixture:** `contracts/fixtures/critical-api-responses.json`

## Problem koji faza zatvara

Raniji ticket incident prošao je minimalni frontend parser test iako stvarni cross-layer ugovor nije bio usklađen:

- parser je prvobitno očekivao pogrešno polje `number` umjesto `ticketNumber`;
- backend list query je računao `totalsAsOf`, ali završni response mapper ga nije slao;
- prazni ili približni ručni fixture nije dokazivao stvarni javni response.

Faza 1 uklanja odvojene, ručno prepisane pozitivne ugovore za critical boundaries i uvodi zajednički reprezentativni fixture.

## Shared fixture sadržaj

Fixture pokriva:

1. current session/capabilities;
2. uspješnu authentication session;
3. MFA-required međustanje;
4. install readiness i summary;
5. nepraznu ticket stranicu sa 44 rezultata;
6. routing coverage stranicu;
7. service catalog batch sa runtime availability i aktivnom formom;
8. permission-sensitive settings registry;
9. config package preview/import report.

Ticket red koristi stvarni javni naziv `ticketNumber` i reprezentativna DTO polja. Ticket envelope obavezno sadrži `totalsAsOf`, `page` i `pageSize`.

## Frontend zaštita

`critical-api-parsers.spec.ts` učitava shared fixture i prosljeđuje stvarne reprezentativne objekte svim critical parserima.

Negativni ugovori i dalje dokazuju:

- pogrešan auth međustatus;
- nedostajuće capability polje;
- pogrešan install counter;
- neobjektni ticket red;
- stari/pogrešni `number` alias bez `ticketNumber`;
- pogrešan routing scalar;
- pogrešan service counter;
- pogrešan settings scalar;
- neispravan config package items oblik;
- kontrolisani `INVALID_API_RESPONSE` i request ID.

Ticket parser ponovo strogo zahtijeva invariantna list-row polja:

- `id`;
- `ticketNumber`.

Permission-sensitive opisna polja ostaju kompatibilna i ne ruše cijelu listu ako javni ugovor dozvoljava njihovo odsustvo.

## Boundary registry

`critical-api-boundary-contract.spec.ts` sada za svaku granicu zahtijeva:

- service fajl;
- parser;
- shared fixture ključ;
- domenskog ownera;
- stvarnu upotrebu `apiRequestValidated`.

Aktuelni owneri su:

- identity;
- install;
- tickets;
- configuration;
- routing;
- services;
- settings.

Novi critical boundary ne može se dodati u katalog bez imenovanog fixture ključa i ownera.

## Backend zaštita

Dodan je čisti mapper:

- `backend/src/modules/tickets/list/to-ticket-list-response-envelope.ts`

`respondTicketListPage` i dalje učitava permission-sensitive ticket redove postojećim backend putem, ali završni javni envelope delegira čistom mapperu.

Direktni backend test učitava isti shared fixture i potvrđuje:

- mapper ne ispušta `totalsAsOf`;
- `ticketNumber` ostaje u javnom redu;
- pagination vrijednosti ostaju iste;
- optional `totalIsCapped` se šalje samo kada je `true`.

Test ne zahtijeva bazu niti generisani Prisma client jer provjerava čisti javni envelope mapper.
