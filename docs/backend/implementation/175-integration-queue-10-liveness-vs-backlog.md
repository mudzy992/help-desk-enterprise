# BA-integration-queue-10: liveness i backlog kao odvojena opažanja

Status: **otvoreno**. Heartbeat je procesno/Redis opažanje, ne dokaz da glavni integration queue ili provider dostavlja. Admin kartica to sada eksplicitno prikazuje. Endpoint dodatno vraća najstariji `createdAt` trenutno dispatchable posla: PENDING ili FAILED čiji retry nije zakazan u budućnosti. Čita se samo timestamp, ne payload. Nema spremnih poslova je različito od DB greške (`unknown`). Redis greška i DB greška obrađuju se nezavisno. Heartbeat predaleko u budućnosti (više od postojećeg stale praga) daje `unknown`, ne lažno `active`.

Opažanje je snapshot na otvaranju/osvježavanju, nije automatski alarm. Vrijeme je **kreiranje posla**, ne vrijeme dospijeća retryja; star FAILED posao može tek sada postati spreman. PROCESSING, DLQ, ugašeni tipovi i zdravstveno stanje providera nisu pokriveni; prazan backlog ne dokazuje isporuku. Nema synthetic joba, per-channel outcome metrika ni end-to-end acceptance dokaza. Query se izvršava pri admin status zahtjevu; indeks `(status, createdAt, id)` postoji, ali nije mjeren query plan ni ponašanje pod velikim backlogom. Testovi uključuju DB integration scenarij, ali potrebni su generated-Prisma/realni PostgreSQL, Redis/two-instance, stalled-worker i provider dokazi prije zatvaranja.
